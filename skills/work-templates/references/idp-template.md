## Nguyên tắc khi điền IDP

### Mục tiêu cụ thể
- Định lượng được, có deliverable rõ
- Mapping 1-1 với nhóm năng lực Senior framework
- ❌ "Học KMP để giỏi hơn"
- ✅ "Ship 1 KMP module ra production, unit test ≥70%, được Tech Lead approve"

### Action
- Chia 3 step, mỗi step có output kiểm chứng
- Không liệt kê "hoạt động" — chỉ những bước thực sự đẩy mục tiêu

### KPI
- Cụ thể, đo được vào cuối Half
- ✅ "Module merged", "2 buổi sharing delivered", "review time < 30p"
- ❌ "Hiểu sâu hơn", "tự tin hơn", "có insight"

### Deadline
- Tuần cụ thể (W##), không "trong Half"
- Stagger qua các tuần, không dồn cuối Half

## Review cadence

- **Weekly**: tick tiến độ trong weekly report (có thể tag từng task vào nhóm năng lực)
- **Bi-weekly**: 1:1 với DM, review tiến độ IDP, điều chỉnh nếu cần
- **End of Half**: tự đánh giá vs Senior framework checklist (xem `senior-framework.md`), tổng kết evidence để gửi DM cho cycle promotion

## Evidence package cuối Half

Khi sắp đến promotion review, gom evidence theo 4 nhóm:

```
1. Innovation
   - Doc đề xuất / PR cải tiến
   - Comment / approval từ Techlead, PM

2. Continuous Development
   - Slide / recording 2+ buổi sharing
   - 1:1 notes với Hiếu, feedback từ Hiếu
   - Tài liệu đúc kết hệ thống

3. Ownership
   - Doc OKRs cá nhân + map với OKRs team
   - Snapshot kanban / weekly plan
   - Meeting notes nơi Dũng support member

4. Android Tech R&D
   - PR security (R8 / Play Integrity)
   - Commit vào guideline team
```
